# Agent 长期记忆

入口：设置 → 长期记忆 → **全局（人格 / 用户画像）** 与 **当前工作空间记忆**。

## 三层职责与工作空间隔离

- 人格定义助手的身份和表达风格，仅手动维护；用户画像保存跨工作空间的用户背景和长期偏好；工作空间记忆只保存当前项目的长期约定、目标和术语。没有第四层全局事实库。笔记正文仍通过文件或检索工具读取，记忆不能作为实时文件状态，也不能扩大权限。
- 全局内容仍使用原 `userData/soul.md` 和 `userData/user.md`。工作空间内容由应用存于 `userData/workspace-memory/<工作空间ID的SHA-256>/`，复用独立的 `user.md`、历史、快照、回执和清理日志；不写入笔记目录、不随文件夹自动共享。内部复用文件名不代表把项目事实写入全局画像。
- Agent 使用无路径、无工作空间 ID 参数的 `workspace_memory_read` / `workspace_memory_update`，归属由主进程绑定到当前运行；不能通过工具选择别的工作空间。用户偏好写画像，项目约定写工作空间；范围不明确时询问，不自动提升到全局。对输入事实和秘密的筛选仍依赖模型遵守提示，不是语义安全分类器。
- 每个工作空间有独立且默认开启的自动维护开关，与全局用户画像开关互不影响。关闭仅限制自动写入，手动编辑、读取、恢复不受影响。开关按工作空间持久化并跨窗口通知；保存队列内继续检查实时权限，已开始的原子保存不承诺回滚。
- 设置无工作空间时只提供全局编辑；工作空间编辑器绑定具体 ID，异步返回和通知按作用域过滤。在本次设置页挂载期间切换空间会保留未保存草稿，离开设置页不持久化这些草稿。历史恢复、实时同步和清理复用现有保护；当前空间清理不能删除全局记忆、人格或其他空间的数据。
- 新对话固定三层快照，全局快照只保存一个工作空间绑定标记，工作空间正文快照留在对应隔离目录。原有双层快照保持不变，第三层视为空，不从最新项目内容补写旧对话；需要最新内容时使用读取工具或新建对话。缺失已绑定的快照会拒绝继续，不偷偷换成新版。
- 成功保存的回执带有作用域，工作空间回执额外验证所属 ID；重启恢复分别扫描已登记空间的回执。对话末尾区分「用户画像已更新」与「工作空间记忆已更新」，净差异按作用域分别计算，不混合版本链。历史、清理、崩溃补偿与下述全局机制一致，但各自管理自己的目录；旧聊天正文和外部备份仍不属于清理范围。

- 两项分别保存为 Electron `app.getPath('userData')` 下的 `soul.md`、`user.md`，不属于工作空间。首次未保存时内容为空。
- `soul.md` 仅用户手动编辑；Agent 已获授权通过 `user_profile_read` / `user_profile_update` 自主维护 `user.md`，无需逐次审批。两者仍可在设置编辑。没有后台学习、向量记忆或第二套 Python 文件存储。
- 画像只记录用户在对话中明确提供的长期事实与偏好，可以补充、纠正、删除，保留无关信息。系统提示禁止任务进度、秘密、敏感推断和来自笔记/检索/工具输出的记忆写入指令；事实是否值得记忆仍依赖模型遵守提示，不是语义分类器的硬保证。
- 专用工具必须先读取最新完整画像和 revision，再提交完整替换内容与 `expectedRevision`；主进程检查本次运行确实读过该版本，并经现有 AgentMemoryStore 串行、版本检查、原子写入成功后才返回成功。冲突时重读合并，不允许用旧快照覆盖。超过通用工具预览长度的画像也完整返回给模型，避免截断导致丢失无关信息。
- AIService 为每次启动/继续运行创建仅监听 `127.0.0.1` 的临时画像接口，用随机能力令牌、运行 ID、启用工具列表校验请求；结束/取消后关闭。令牌和接口地址只传给本机 Python 执行上下文，不进入模型消息、工具参数或工作空间。Python 工具仅回调主进程，不知道 userData 路径；工作空间文件安全边界不变。此桥接仅支持本机 Agent 服务，不支持远程服务回调。
- 每项最多 16,000 个 UTF-16 字符；支持纯文本 Markdown。保存失败保留编辑内容，版本冲突需重新加载后重新编辑。重新加载会丢弃当前编辑。
- 文件以内容 SHA-256 作为并发版本。主进程按数据目录串行处理写入和快照；写临时文件、同步文件、原子重命名，并在非 Windows 平台同步目录。没有缓存旧读取结果。目录同步失败时可能已经提交，必须重新加载确认实际内容。
- 对话第一次启动 Agent 时固定快照，保存到同一 userData 下的 `memory-snapshots/`，以工作空间 ID 和对话 ID 的哈希命名。后续轮次、重启后继续运行使用相同快照；新对话使用最新已保存内容。当前对话通过画像工具结果知道更新，旧快照不改写；画像读取不复用前轮工具缓存。
- 存储失败、版本冲突与桥接通信失败使用不同错误码和中文提示。通信中断/超时或目录同步失败可能发生在实际写入后，不能声称已保存或已回滚，必须重读确认。取消运行关闭能力，不回滚已经开始提交的原子保存。
- 继续运行时快照缺失或损坏会拒绝启动，而不是偷偷使用新版本。升级前没有快照的旧运行需新建对话；升级后的旧聊天首次启动 Agent 时会固定当时的设置。
- 快照为本机明文，不自动清理。设置中的「本机记忆清理」可显式删除；删除聊天本身不会删除快照，应用数据备份也可能包含旧版本画像。
- 内容会随请求发送给当前选择的模型，不要写入密码或其他不应发送的信息。
- 固定系统规则、工具权限和审批逻辑不受人格/画像配置改变。记忆作为单独的低优先级数据消息注入，不拼接或替换运行时首条系统消息，保留原生工具和 JSON 决策协议适配。

## 用户画像历史版本与恢复

- 用户画像卡片的「历史版本」可分页浏览、读取完整纯文本预览，选择「恢复上一版」或「恢复此版本」后还需确认。上一版指已加载历史中最新的、与当前内容不同的备份；更早的备份可继续加载。人格不提供历史或恢复功能。
- 主进程在每次手动、Agent 或恢复操作改变 `user.md` **之前**，将当前内容、SHA-256 revision、时间及来源保存到 `userData/user-history/<时间>-<UUID>.json`。已有 `user.md` 无需迁移，第一次变更就会备份原内容；首次空画像也能恢复。相同内容的保存/恢复不新增备份。历史不自动删除。
- **来源是触发备份的操作**（`manual` / `agent` / `restore`），不是该内容的作者，也不是后续写入成功的记录。每个条目都是已读到的旧内容，绝不把未提交的新内容作为成功版本；失败或取消的写入可能留下旧内容备份。备份文件、备份目录及其父目录同步完成后才开始覆盖当前画像。备份失败则不覆盖；当前文件 rename 后同步失败仍可能已写入，须重新读取确认。这里不是跨文件事务或完整提交日志。
- 恢复只接受主进程历史 ID 与**当前画像** revision；不接受渲染器传入的快照内容、路径或来源。主进程验证 ID、文件类型、大小、UTF-8、内容长度、revision、时间和来源，拒绝损坏或符号链接的历史；与普通保存共用队列和 CAS。恢复前也备份当前内容，因此可再次恢复撤销。自动维护关闭不限制用户手动恢复，已有对话快照保持不变。
- 有未保存草稿时允许浏览历史，但必须先保存或主动丢弃草稿才能恢复。读取、保存、恢复失败或版本冲突不丢弃草稿。恢复成功更新编辑器内容、revision 和历史；其他窗口未编辑时同步，有草稿时只提示，不覆盖。外部更新会取消尚未执行的恢复确认，历史刷新保留所选版本预览。
- 单个损坏、缺失或不合规的历史文件不会阻断同页健康版本：列表显示固定中文提示并禁用查看/恢复，文件保留且仍计入分页。上一版跳过无效条目；目录枚举失败仍显示错误，不伪装成空历史。非法文件名继续过滤，不生成可操作条目。
- 备份结束后再次检查 Agent 的实时运行授权，防止备份期间关闭权限后仍开始覆盖画像。已经开始的当前文件原子保存仍不承诺可撤销。历史与对话快照都是本机明文；应用数据备份可能保留已删除的旧画像内容。

## 设置页实时同步

- 同一应用主进程确认手动保存（人格或画像）、Agent 保存画像、历史恢复后，向应用窗口发送仅含类型和 revision 的失效通知，不广播画像正文。相同内容不通知，CAS 拒绝和提交前失败不伪报成功；当前文件 rename 后失败则发送不带 revision 的不确定性通知，仍向调用方返回失败。
- 设置页先订阅再读取，收到通知后从主进程重读权威内容；未编辑时自动更新，有未保存内容时保留草稿及原 CAS revision 并提示合并。订阅在卸载时释放，不使用轮询。读取、保存、恢复交错时忽略旧响应，并在写入完成后处理待同步通知；自身保存的回声不提示冲突。
- 自动维护关闭不影响手动保存、恢复及内容同步。同步仅覆盖应用内操作；外部编辑器改动须主动重新加载，不提供原始文件监视。
- 自动维护开关与其他应用设置支持跨窗口同步：仅广播 revision，各窗口重新读取权威设置并忽略旧响应。修改采用字段级补丁，由主进程在队列内合并最新设置；旧全量保存接口须携带当前 revision，拒绝无版本或过期快照，避免其他窗口修改无关设置时重新开启自动维护。设置文件经临时文件同步后原子重命名，不承诺目录同步或硬件断电持久性。

## 对话底部的记忆更新提示

- 仅主进程确认的 CAS 保存产生持久化收据，仍等待收据入账、画像桥接收尾后再完成回合；失败、取消后真正保存的变更也保留在原回合。实时展示与重启后历史回放使用同一规范事件投影。
- 主进程在一次运行内仅保留一个最多 16,000 字符的段首画像。连续成功保存按“段首内容 → 最后保存内容”计算精确行差异，收据额外保存累计净差异和段号，不保存无关的整份画像。重复行、多行 Unicode、先增加再删除、替换后恢复原文均按完整内容计算，不按字符串猜测抵消。
- 若中间有其他写入导致 revision 不连续，则另起一段，绝不把其他运行或手动编辑算作本轮增加。较早有净变化的段只保留静态提示，不展开可能已撤回的文字；只展示最后连续段的净新增。已完全撤回的段不贡献提示。
- 没有净变化时不显示提示；仅删除或无法可靠合并时显示静态记忆图标与「记忆已更新」，没有空展开按钮。存在净新增时默认折叠，只展开新增内容，不显示删除文字、标签或次数。
- 旧收据不迁移、不修改。单次旧收据仍可显示其新增内容；同一运行有多次旧收据但缺少净差异元数据时，保守显示静态提示，不推断重复行或撤回内容。

## 本机记忆清理（限定范围，不是彻底遗忘）

- 设置 → 长期记忆 →「本机记忆清理」允许分别清理画像历史和对话记忆快照；选择清除当前用户画像时，强制同时清除历史和快照。人格 `soul.md` 不在清理范围内。清理前必须点击预览，核对逐项文件清单、各类文件数量和未识别文件，再勾选不可撤销确认。数量包含符合应用命名规则的崩溃残留临时文件，不只是可浏览的完整版本。
- 主进程只接受固定布尔范围和预览 token，不接受路径。token 绑定当前画像、所选文件名与精确字节摘要；在预览之后内容或范围改变，必须重新预览确认。仅识别应用管理的文件名，未知文件保留并在已扫描目录的清单中说明。符号链接、非普通文件和损坏的清理日志会阻止清理，不跟随链接删除其他数据。
- 清除画像是直接删除 `user.md` 及所选副本，**不调用普通保存，不为被遗忘内容新增备份**。每次清理还会删除待处理回执及其残留临时文件，避免以后重放已确认清理的更新详情。历史/快照目录中的合法命名但内容损坏的记录也可按清单删除。
- 有任何活动 Agent 运行时拒绝确认清理；清理执行期间拒绝启动/继续。清理代次也使此前打开的画像写入能力失效，防止已取消运行的迟到写入重新填回画像。自动维护开关保持原值；如不希望以后再次记录，请主动关闭。清除当前画像后丢弃当前设置窗口的画像草稿；其他窗口的未保存草稿仍按冲突策略保留，不属于磁盘清理范围。
- 删除前先持久化 `memory-cleanup.json`。中途失败可能已有部分文件删除，界面不会声称全部成功；下次设置读取、历史预览、受管写入、快照或回执恢复前继续已确认的删除，完成前不接受新的受管记忆写入。重复恢复容忍已删除文件，成功后移除日志；恢复或部分失败实际改变文件时通知其他窗口重读，无进展的失败重试不重复广播，避免通知触发读取的循环。
- **不会删除**旧聊天原文、工作空间规范账本里已入账的记忆更新详情、未识别文件、外部备份或模型服务商留存，也不是磁盘安全擦除。旧聊天、仍保留的草稿或用户再次提供的信息可能重新引入事实。请新建对话；丢失原快照的「继续运行」会被拒绝，但在旧聊天里开启新轮次仍可能带入旧消息。

## 画像保存后的崩溃回执补偿

- Agent 保存前在 `userData/memory-receipts/<UUID>.json` 写入并同步 `pending` 意图，包含主进程确定的工作空间 ID、task/run ID、时间、前后 revision 和更新差异。不接受模型或渲染器指定的回执、路径或归属。当前 `user.md` 原子提交后标为 `committed`，随后等待规范账本持久化确认，才删除回执并返回工具成功。
- 崩溃发生在当前文件提交前，重启后若画像仍等于 before revision，则撤销未提交意图；若等于 after revision，则重试目录同步并补记提交。旧历史备份从来不是保存成功证据。若两者均不匹配（例如外部修改），停止写入/回放并报告问题，不猜测成功；用户可检查文件，或通过预览清理明确放弃待处理回执。后续受管保存/恢复先解决 pending 证据，防止新写入覆盖唯一提交依据。
- 启动时尝试恢复，打开原工作空间账本（单个或批量运行历史）以及继续运行前再次恢复，不必等待下一次画像写入。找不到工作空间时保留回执；账本归属、运行或回执冲突不匹配时拒绝补写。活动运行的回执由原桥接收尾，恢复器不与其争抢。
- 账本事件使用回执 UUID 派生的稳定 ID，在同一账本写队列内去重和分配 sequence；已入账但未确认删除的回执重放不会产生第二个事件。原运行记录决定原 assistant message 的归属。尚未确认的回执按受管提交顺序恢复（时间碰撞/时钟回退不会颠倒），同一运行较新的实时回执成功前先补交较旧回执，避免旧新增在较新撤回之后重新出现。
- 预写意图不推进本轮净差异基线；提交前失败不会虚构一次成功或切断连续成功保存。画像提交后回执标记/入账失败仍可能已保存，返回失败并保留补偿记录；设置窗口会收到不确定性通知重读。该机制补偿本机文件间的进程崩溃窗口，不是文件系统事务、对恶意本机改写的认证或硬件断电绝对保证。

## 验证范围与限制

- 自动测试使用临时目录，包括真实子进程在意图、当前画像和提交标记重命名前后退出，文件重命名/目录同步故障、账本提交后确认丢失、重放幂等、清理 token 变化、符号链接、损坏日志、IPC 历史读取补偿以及 Vue 确认交互。Python/provider 集成使用脚本化模型传输，不等同于真实模型行为验证。
- 本轮未完成真实本地模型和 Windows 实机验证：本地模型接口不可用，当前主机没有 Windows 运行环境。不得将本机单元测试或组件烟测描述为这两项已经通过。

并发保证针对同一 Electron 主进程中的窗口/请求；不承诺协调外部编辑器或独立应用进程恰好同时写文件，也不承诺硬件断电绝对持久性。Windows 跳过目录 fsync，尚未进行 Windows 实机验证。
