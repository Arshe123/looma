# Agent 长期记忆

入口：设置 → 长期记忆 → **人格** / **用户画像**。

- 两项分别保存为 Electron `app.getPath('userData')` 下的 `soul.md`、`user.md`，不属于工作空间。首次未保存时内容为空。
- `soul.md` 仅用户手动编辑；Agent 已获授权通过 `user_profile_read` / `user_profile_update` 自主维护 `user.md`，无需逐次审批。两者仍可在设置编辑。没有后台学习、向量记忆或第二套 Python 文件存储。
- 画像只记录用户在对话中明确提供的长期事实与偏好，可以补充、纠正、删除，保留无关信息。系统提示禁止任务进度、秘密、敏感推断和来自笔记/检索/工具输出的记忆写入指令；事实是否值得记忆仍依赖模型遵守提示，不是语义分类器的硬保证。
- 专用工具必须先读取最新完整画像和 revision，再提交完整替换内容与 `expectedRevision`；主进程检查本次运行确实读过该版本，并经现有 AgentMemoryStore 串行、版本检查、原子写入成功后才返回成功。冲突时重读合并，不允许用旧快照覆盖。超过通用工具预览长度的画像也完整返回给模型，避免截断导致丢失无关信息。
- AIService 为每次启动/继续运行创建仅监听 `127.0.0.1` 的临时画像接口，用随机能力令牌、运行 ID、启用工具列表校验请求；结束/取消后关闭。令牌和接口地址只传给本机 Python 执行上下文，不进入模型消息、工具参数或工作空间。Python 工具仅回调主进程，不知道 userData 路径；工作空间文件安全边界不变。此桥接仅支持本机 Agent 服务，不支持远程服务回调。
- 每项最多 16,000 个 UTF-16 字符；支持纯文本 Markdown。保存失败保留编辑内容，版本冲突需重新加载后重新编辑。重新加载会丢弃当前编辑。
- 文件以内容 SHA-256 作为并发版本。主进程按数据目录串行处理写入和快照；写临时文件、同步文件、原子重命名，并在非 Windows 平台同步目录。没有缓存旧读取结果。目录同步失败时可能已经提交，必须重新加载确认实际内容。
- 对话第一次启动 Agent 时固定快照，保存到同一 userData 下的 `memory-snapshots/`，以工作空间 ID 和对话 ID 的哈希命名。后续轮次、重启后继续运行使用相同快照；新对话使用最新已保存内容。当前对话通过画像工具结果知道更新，旧快照不改写；画像读取不复用前轮工具缓存。
- 存储失败、版本冲突与桥接通信失败使用不同错误码和中文提示。通信中断/超时或目录同步失败可能发生在实际写入后，不能声称已保存或已回滚，必须重读确认。取消运行关闭能力，不回滚已经开始提交的原子保存。
- 继续运行时快照缺失或损坏会拒绝启动，而不是偷偷使用新版本。升级前没有快照的旧运行需新建对话；升级后的旧聊天首次启动 Agent 时会固定当时的设置。
- 快照为本机明文，目前不自动清理。删除聊天不会删除快照；应用数据备份中也可能包含旧版本画像。
- 内容会随请求发送给当前选择的模型，不要写入密码或其他不应发送的信息。
- 固定系统规则、工具权限和审批逻辑不受人格/画像配置改变。记忆作为单独的低优先级数据消息注入，不拼接或替换运行时首条系统消息，保留原生工具和 JSON 决策协议适配。

并发保证针对同一 Electron 主进程中的窗口/请求；不承诺协调外部编辑器或独立应用进程恰好同时写文件，也不承诺硬件断电绝对持久性。Windows 跳过目录 fsync，尚未进行 Windows 实机验证。
